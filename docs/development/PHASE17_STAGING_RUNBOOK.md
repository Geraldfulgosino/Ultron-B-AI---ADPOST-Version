## 5. RLS test requirements

Run plan §8 with **real JWTs**. Sign in as each seeded user through the anon key; never use the service role for these checks.

Seed ⚠: 2 brands (A, B) in one agency, plus one brand in a second agency. Users: agency owner, brand-A owner, admin, manager, member, viewer, a client linked to client A1, a brand-B manager, and an unrelated signed-up user with no memberships.

For **each** brand-owned table, assert:

- A brand-A user cannot select, insert, update or delete brand-B rows.
- A `viewer` reads but cannot write. A `client` reads only rows whose `client_id` is theirs, and no staff-only tables (agents, chat, tasks, knowledge, executions).
- Agency staff read both brands in their agency and nothing in the other agency.
- `anon` sees zero rows everywhere.
- Users cannot insert `messages` with `author_type <> 'user'` or someone else's `author_user_id`.
- Only owners or agency staff can grant or remove the `owner` role.
- Approvals: only admins decide, and `decided_by` must equal `auth.uid()`.
- Secrets tables (`integration_secrets`, `n8n_connection_secrets`) return nothing to `authenticated`.
- Storage: cross-brand read, write and delete under `brand-knowledge/{otherBrandId}/…` is denied. `report-exports` has no direct read.
- Realtime: a brand-B subscriber receives no brand-A `messages` events.

Automate this as `apps/adpost-web/src/test/contract/supabase.contract.test.ts`, which runs `runBackendContract()` against the seeded staging project and is skipped unless `SUPABASE_CONTRACT_URL` is set. Add a SQL-level pgTAP suite (`supabase/tests/rls.test.sql`, run by `supabase test db`) for the table-by-table matrix.

## 6. Mock-to-live adapter replacement

The UI depends only on `src/data/contracts.ts` (`Backend` = `auth` + `api()` + `subscribe()`). Live support means adding `src/data/supabase/` next to `src/data/local/`, with no page changes.

1. **Dependency** (needs a security review first): `@supabase/supabase-js`, pinned to an exact version at least two weeks old.
2. **Bootstrap:** `AuthApi.currentSession()` is synchronous, and Supabase's `getSession()` is async. In `main.tsx`, `await` the session before `createRoot().render()`, then keep it updated through `onAuthStateChange`.
3. **Auth gaps:** add `requestPasswordReset(email)` and `updatePassword(password)` to `AuthApi`, plus a `/reset-password` route. Implement both in the local adapter too, so the contract suite covers them.
4. **Reads/writes:** map each `*Api` to table queries. Errors map to `src/data/errors.ts` (an RLS denial or zero rows becomes `AccessDeniedError` or `NotFoundError`, as the contract tests expect; a JWT failure becomes `AuthError`).
5. **AI and side effects** become Edge Function calls: `agent-execute` replaces `src/data/local/engine.ts`, and `orchestrate-group` replaces `orchestrator.ts`. Then `report-export`, `ga4-sync`, `gsc-sync` and `n8n-dispatch`. Model keys live only in function secrets. Functions re-check access with the caller's JWT; they do not trust ids from the browser.
6. **subscribe()** wraps Realtime channels (`messages`, `agent_executions`, `approval_requests`) filtered by `brand_id`.
7. **Switch:** `VITE_BACKEND=supabase` selects the adapter in `main.tsx`, and `local` stays the default. The local "dev accounts" hint already hides itself when the backend isn't `local`.
8. **Gate:** `npm test` must keep passing (the local adapter is unchanged), and the staging contract suite plus RLS suite must pass before any Phase 18 work.
